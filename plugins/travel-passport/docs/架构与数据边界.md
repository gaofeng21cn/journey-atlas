# Journey Atlas 架构与数据边界

Journey Atlas 的核心是“源表 → 只读装载 → 派生账本 → 地图/护照/Agent 视图”。同一份用户数据同时服务静态导出、离线网站和 OPL App，不建立第二份个人事实库。

## 四类边界

| 类别 | 内容 | 默认位置 | 是否进入 Git |
| --- | --- | --- | --- |
| 维护源 | 地点、行程、移动、到访实例、核定和证据引用 | 用户配置的 `dataSource.path` 或 Obsidian 连接器 | 否 |
| 通用实现 | schema、导入器、连续性、重建、地图和导出 | `scripts/`、`src/`、`test/` | 是 |
| 公共资源 | 行政边界、投影、地区目录和许可说明 | `data/`、`NOTICE.md` | 按来源许可 |
| 派生物 | PNG、SVG、HTML、汇总 CSV、检查回执和缓存 | 用户配置的 output / ignored runtime | 否 |

默认数据源是 `data/source/`，也可以在 `data/atlas-config.json` 中设置：

```json
{
  "dataSource": { "type": "csv-directory", "path": "data/source" },
  "output": "./outputs",
  "coverage": []
}
```

Obsidian 连接器只负责把已有维护表映射到统一源表；它不是渲染器的隐式依赖。所有输入在进入 `atlas-data.mjs` 前都按 `scripts/schema.mjs` 校验。

## 数据模型

- 地点层保存稳定地点编号、行政归属、代表坐标、级别和访问状态。
- 行程层保存一次活动的时间窗口、基地、闭环/开放边界和关联交通编号。
- 移动层保存有向节点序列、方式、距离、时长、来源类型、计程口径和证据。
- 城市证据层保存 GPS 片段、照片位置和可重建的城市内移动；它投影到同一移动账本，不重复累加全球里程。

地点、行程和移动之间必须通过编号和显式段序建立关系。展示名称、机场服务城市和地图弧线只属于显示层，不能替代节点引用。事实核定和合理重建分别保存；`model` 数值可以用于可视化，但不能伪装成 `observed`。

## 模块职责

- `schema.mjs`：字段、版本和更新合同。
- `source-data.mjs`：初始化、导入、CSV/JSON 源包和配置解析。
- `atlas-data.mjs`：只读装载、绑定地点/节点、派生全局账本。
- `update-atlas.mjs`：唯一正式写入入口，提供预览、证据校验、备份和并发保护。
- `global-mobility.mjs`、`reconstruct-city.mjs`、`hub-links.mjs`：重建和接续候选；不绕过核定写回源表。
- `site-data.mjs`、`src/`、`render-*.mjs`：地图、护照和年度卡呈现。
- `app-contribution.mjs`：OPL 结构化状态、摘要、年度和分区视图。
- `verify-all.mjs`、`check-site.mjs`：源码、数据、连续性、资源和离线网站验收。

## 运行边界

构建只写派生目录；导入只写用户指定的数据源。私人路径、姓名、GPS、照片、票据和补丁由 `.gitignore` 保护。公共地图文件的来源、许可和署名见 [NOTICE.md](../NOTICE.md)，受限资源可通过下载器在本地生成，不能假定代码许可证覆盖它们。
