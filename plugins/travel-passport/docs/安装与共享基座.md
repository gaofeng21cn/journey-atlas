# 安装与共享基座

Journey Atlas 是一个软件产品，稳定 Package ID 为 `travel-passport`。OPL 软件中心将其作为应用纳管，默认安装正式版；开发 checkout 是同一产品的另一份安装，须显式接入或激活，不因源码版本较高而替换正式版。已激活的 Package carrier 是 Agent 和共享 UI 唯一的代码入口。

| 内容 | 所在位置与管理方式 |
| --- | --- |
| 正式版代码、公共地图、锁定 npm 依赖 | carrier 的版本化安装目录；OPL Package 原生安装器负责安装、更新和卸载 |
| 开发代码 | 用户选择的 Git checkout；更新正式版不修改开发文件 |
| 旅行资料与配置 | 用户的独立工作区；`data/atlas-config.json` 绑定现有 Obsidian 或本地表格 |
| 图片、网页、构建记录 | 工作区配置的输出目录；均为可重建派生物 |
| 变更回执与回滚副本 | 工作区的 `private/evidence/updates/` 和 `data/history/` |

## Agent 与人共享同一个入口

`node <安装目录>/journey-atlas.mjs --workspace <工作区> ...` 始终执行当前安装中的代码。它不执行工作区中的 `package.json`、脚本或二进制；工作区仅提供配置、资料及产物。`version` 可回读实际版本与安装路径，`status --json` 回读相同来源的状态，`update --dry-run` 预览资料变更，正式写入沿用既有 `update` 的源版本和回执合同。

OPL 共享 MCP App 使用同一安装的 `app-contribution.mjs`，由既有 workspace binding 提供工作区路径。缺少工作区或依赖时返回明确的首次配置状态，不回退到旧源码副本。状态、总览、年度和地区视图都只是同一来源的投影；复杂地图仍通过本地离线网页浏览。

首次 CLI 业务调用和共享视图中的“初始化运行环境”都使用 `npm ci --ignore-scripts --no-audit --no-fund`。`package-lock.json` 固定下载版本与完整性，禁止依赖安装脚本；安装结果逐项回读。共享视图的普通读取不会启动依赖安装。导出图片时按需复用或安装 Playwright Chromium，浏览器缓存沿 Playwright 原有路径管理。

## 复用现有知识与凭据

优先复用已在 OPL 共享资源登记并授权的旅行知识来源，常用位置是 Obsidian。Agent 使用 Framework 的 `opl knowledge read-source` 读取已知来源，按其 `verify-dependencies` 和 action revalidation 合同检查有效性；缺失信息才补充询问。Journey Atlas 的 `dataSource` 保存到原始表格和允许正文目录的绑定，不能把凭据、知识正文或另一个 registry 塞进 Package。

通用旅行偏好与资料库归原知识 owner；Journey Atlas 只拥有旅行数据契约、受审阅的源表变更、地图和产物回读。当前本地功能不需要独立网络账户，因此不新建凭据管理。将来增加邮箱或外部服务导入时，接入 OPL Connect 的授权引用，不保存平台密码或复制 provider。

## 发布与兼容

公开制品入口为 `ghcr.io/gaofeng21cn/one-person-lab-packages/travel-passport:latest-stable`。Framework 持有目录 projection、签名校验、安装和版本选择；本仓持有产品版本、载荷和领域行为。

`package-runtime-files.json` 逐文件声明公开运行载荷；`npm run package:sync` 生成 `plugins/travel-passport/`，`npm run package:check` 同时核对源文件、生成副本和 content lock。不得手改生成副本。私人配置、源表、输出、node_modules、凭据和缓存均不得进入载荷。稳定 Package、插件及 contribution IDs 保持兼容，名称始终显示 Journey Atlas。

卸载软件后再次安装并绑定原工作区即可继续使用；不需要复制旧插件目录中的旅行资料。已有源码工作区继续支持原 `npm run ...` 命令，显式开发操作与受管安装分别执行。
