# 输入目录约定

`inputs/` 保存本地来源配置和待合并补丁，`data/source/` 保存通用源表，`private/evidence/` 保存稳定核定证据，`private/runtime/` 保存可重建中间产物。这些目录均被 Git 忽略。

一次导入以版本化 JSON bundle 提交，字段由 `scripts/schema.mjs` 定义。`npm run import:data -- --input <bundle.json>` 会检查未知字段、重复编号和已存在记录冲突；日常事实修订使用统一 `npm run update` 入口，先预览再应用。

## 绑定已有目录

配置保存在被 Git 忽略的 `data/atlas-config.json`。通过 `TRAVEL_PASSPORT_CONFIG=/绝对路径/config.json` 可以让所有 CLI 使用另一份配置。已有源表不需要搬迁或复制：

```json
{
  "referenceRoot": "/已有知识目录",
  "dataSource": {
    "type": "csv-directory",
    "path": "旅行数据/维护表",
    "files": {
      "全旅程数据点-行程.csv": "子目录/现有行程.csv"
    },
    "referenceRoots": ["旅行正文", "旅行证据"]
  },
  "output": "/单独的输出目录",
  "coverage": []
}
```

`files` 的键是 `scripts/schema.mjs` 定义的逻辑表名，只需填写覆盖项。`csv-directory` 的默认文件为 `flights.csv`、`movements.csv`、`journeys.csv`、`visits.csv`、`city-places.csv`、`city-moves.csv`、`city-journeys.json`、`city-evidence.json` 等；完整映射由 `scripts/source-data.mjs` 持有。

Obsidian 自定义布局使用同一配置：`type` 为 `obsidian`，`path` 为 Vault 根，`tableDirectory` 为源表相对目录；`files` 和 `referenceRoots` 用法相同，正文链接相对 Vault 根。省略布局字段时兼容旧旅行区与表目录，已有 `vault` 配置无需修改。

表映射、正文目录和正文引用必须使用根内相对路径，不能含 `..`、绝对路径或越界符号链接；源表根和正文基准根本身可以是绝对路径。正式表不能映射到同一文件。明确声明 `referenceRoots` 同时限定正文解析与存储统计；便携源省略时，正文兼容解析根为 `referenceRoot`，存储统计仍仅扫描源表目录。

原始照片、定位、机票和邮件附件留在使用者自己的原件库。源表记录证据引用和核定依据，不复制原件到代码仓库。公共配置和虚构示例放在 `data/*.example.json` 和 `examples/`。

已应用的补丁不再作为后续构建输入。需要长期回溯时归入用户自己的历史备份，不将旧快照自动加载回来。
