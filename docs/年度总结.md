# 年度总结

“年度总结”是旅行护照中统一的年度表达入口。同一年度数据可生成单张总览或固定九张的故事版，并切换主题与风格。

## 使用

在 OPL App 打开“年度总结”，选择“制作年度总结”，提供年份和可选主题、风格、形式及待飞口径。生成后打开“年度总结”页面，可在本机切换样式、查看整组卡片并逐张保存 PNG 或可编辑 SVG。旅行地图顶部也有“年度总结”入口。

```sh
node journey-atlas.mjs --workspace <私人工作区> review --year 2026 --theme life --style paper --format single --include-planned
node journey-atlas.mjs --workspace <私人工作区> review --year 2026 --theme travel --style night --format story
```

| 维度 | 可选值 |
| --- | --- |
| 主题 | `life` 创造与行走；`travel` 旅行与移动；`creation` 创造与 AI |
| 风格 | `paper` 奶油纸色；`night` 午夜航线；`blueprint` 蓝色护照 |
| 形式 | `single` 单张；`story` 固定九张，按主题组织朋友圈九宫格 |
| 待飞 | `--include-planned` 纳入同年度计划；`--exclude-planned` 仅已发生记录；省略沿用年度配置 |

原有 `annual --year 2026` 继续生成地图式年度旅行护照；新能力统一使用 `review`。产物默认位于既有 output 下的 `annual-reviews/`，包括总入口 `index.html`、年份/主题/风格/形式目录、每页 PNG/SVG/HTML 与清单。不同年份和风格有独立路径。

## 年度配置

复用私人工作区 `data/annual-config.json` 的 `years`，不复制旅行源表。每年配置已有的基地、截止日期、年度片段，并按需要增加 `review`：

```json
{
  "years": {
    "2026": {
      "basePlaceId": "HOME",
      "asOf": "2026-11-30",
      "review": {
        "theme": "life",
        "style": "paper",
        "format": "single",
        "includePlanned": true,
        "title": "把想法带到远方",
        "github": {
          "activeDays": 180,
          "commitContributions": 2400,
          "repositoriesWithCommits": 6,
          "longestStreakDays": 42,
          "queriedOn": "2026-11-30"
        },
        "tokscale": {
          "totalTokens": 1200000000,
          "cacheReadPercent": 80,
          "queriedOn": "2026-11-30"
        },
        "memory": {
          "titleLabel": "移动的节奏",
          "range": {"from": "2026-10-01", "to": "2026-10-20", "mode": "飞机"},
          "lines": ["这段时间，{departures} 次出发、{count} 段飞行", "{km} 公里 · 飞行约 {hours} 小时"]
        }
      }
    }
  }
}
```

示例数字为虚构。GitHub 和 Tokscale 接受已核快照，不需要新增账号授权，也不会自动抓取。缺少某主题的数据时，省略对应页面；单独选择没有数据的创造主题会提示补充快照。`review.projects` 可提供 `{name, description}` 的代表作品。

## 模型与边界

`scripts/annual-data.mjs` 持有年度旅行统计和时间窗口片段。显式纳入待飞时，只增加当年有效计划移动，不用计划激活地面到访、城市或国家，也不改写实际资料截止日。窗口片段继续按其已发生移动汇总。时长和里程沿用源记录的已知、参考与模型身份；分享图用“飞行航段／飞行里程”和约数表述，统计口径保存在清单。

`scripts/year-review.mjs` 组合既有旅行账本与可选年度快照，`src/year-review.mjs` 拥有主题、分页和通用 SVG 模板。CLI、离线年度页面和 App 读取同一模型；切换风格不重新统计或改动源表。HTML 只包装可编辑 SVG；本机 Playwright 负责批量 PNG 导出，离线页面用同一 SVG 生成单张 PNG。正文均转义，画布为1200×1600；故事版固定九张：封面、七张有数据依据的内容页与年度收束；资料不足时提示补充所缺快照，单卡继续可用。

新样式以这次经 RedCube 制作并审阅的年度卡为参考。它们属于应用中的可复用模板；每次生成不是一次新的 RedCube 领域任务。需要自由视觉设计时仍可把同一年度数据交给 RedCube。

本机生成与安装、源码主线集成和公开 Package 发布分别验收。个人年度配置和导出始终留在私人工作区及其 output；通用仓库只包含代码、虚构样例和测试。

## 故事版的视觉结构

故事版按内容分配独立构图，统一姓名、年份与页码即可识别同一组作品；各页不复用同一套大数字框架。背景明暗与文字对齐随内容改变，主要文字和数字以手机打开图片后的尺寸校核。

| 页面 | 版式与依据 |
| --- | --- |
| 封面 | 完整年份与年度主题形成主视觉，曲线连接创造、协作与行走；不放统计图。 |
| GitHub | 代码括号框住提交贡献，活跃天数与仓库数在下方并列；缺少逐日快照时不生成贡献热力日历。 |
| 连续活跃 | 整页突出连续天数，点阵对应这段连续记录，并换算为周与天；不补造起止日期。 |
| AI 协作 | Token 总量先行，流线构成协作主题的主视觉。 |
| Token 构成 | 单独一页用环形图表达缓存读取及其他 Token，保留同一快照的占比。 |
| 飞行 | 航段数与标题错位排布，中部按真实机场坐标绘制年度航线，底部呈现飞行里程；地图只是显示线形。 |
| 移动强度 | 在选定片段内以出发节点、航段数、里程与约数时长组织页面；未提供数值来源时使用原片段文字。 |
| 最远到访地 | 目的地名称成为标题，圆形地图连接基地与该城市，标明两地直线距离；不把直达示意当作实际航班。 |
| 代表作品 | 使用作品清单的编辑排版；只在有作品快照时出现。 |

三种风格沿用各自色系，同时调整字体与图形细节。开放许可的 Manrope 和 DM Serif Display 随载荷交付，离线页面与独立 SVG 内嵌展示字体；PNG 下载保持同一版式。公共地图与字体由 `scripts/year-review-assets.mjs` 单独装载，在年度页面只嵌入一次，年度数据模型继续只保留事实。


故事版九张为固定合同，CLI、App 和离线预览使用同一分页规则。综合主题默认依次为封面、GitHub、连续活跃、AI 协作、Token 构成、飞行、移动强度、最远到访地和年度收束。有代表作品时替换其中一张内容页；旅行与创造主题分别改用其自身的距离、频率、时长或活跃、仓库、提交密度等维度，不用空白页填满九宫格。导出文件按01—09排列。
