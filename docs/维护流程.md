# Journey Atlas 维护流程

## 第一次使用

```sh
npm install
npm run init:data -- --source data/source
```

将 `examples/` 的虚构示例替换为自己的地点、行程和交通数据，或由 Agent 调用 `importSourceBundle()` 导入版本化数据包。不要把原始照片、GPS、机票或邮件放进仓库。

## 日常更新

1. 在用户自己的源目录或 Obsidian 中修改事实源。
2. 执行 `npm run status -- --json` 查看当前输入和输出是否一致。
3. 对增量补丁先执行 `npm run update -- --input <patch.json> --dry-run`。
4. 预览通过后执行同一命令（去掉 `--dry-run`），再运行 `npm run build`。
5. 用 `npm run check:data`、`npm test` 和 `npm run site:check` 验收。

正式写入由 `update-atlas.mjs` 统一处理：按稳定编号合并、检查字段和证据、保存备份，并拒绝未知列、重复编号、未接入节点和日期矛盾。导入器只更新用户自己的源目录，不把数据复制进通用代码。

## 产物与清理

输出目录只保留最新图片、HTML、派生表和构建清单。缓存放在被忽略的 `data/site-cache/` 或 `private/runtime/`，可用 `npm run prune:cache` 清理。历史源表和证据由使用者自己的备份策略负责，不能把 Git 历史当成个人事实源。

## Agent 入口

OPL 贡献读取使用：

- `travel.passport.v1#status`
- `travel.passport.v1#overview`
- `travel.passport.v1#annual`
- `travel.passport.v1#regions`

这些入口只读取状态和派生产物引用；复杂地图继续通过离线站点打开。
